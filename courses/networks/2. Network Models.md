# 2. Network Models, Layers and Protocols

## 2.1 Layered Models and Encapsulation

A layered model divides the complex task of network communication into a set of discrete, hierarchically organised functions. Each layer is responsible for a specific aspect of communication and interacts only with the layers directly above and below it. This separation of concerns offers several practical advantages.

First, it simplifies design and implementation: engineers working on a transport protocol do not need to concern themselves with the physical medium carrying the signal. Second, it promotes interoperability, since any implementation of a given layer can be substituted for another, provided it respects the interface with adjacent layers. Third, it facilitates troubleshooting, because a fault can be isolated to a specific layer without requiring a full-stack analysis.

The concept of a service is central to layered models. Each layer provides a service to the layer above it and consumes the service offered by the layer below. The rules and conventions governing communication between peer layers on different hosts are defined by protocols. The interface between adjacent layers on the same host is called a service access point.

#### Protocol Data Units

As data passes down the layer stack on a sending host, each layer adds its own control information in the form of a header (and sometimes a trailer). This process is called encapsulation. The resulting unit of data at each layer has a specific name, collectively referred to as a Protocol Data Unit.

| Layer (OSI) | PDU name |
|---|---|
| Application / Presentation / Session | Data |
| Transport | Segment (TCP) / Datagram (UDP) |
| Network | Packet |
| Data Link | Frame |
| Physical | Bit |

On the receiving host, the process is reversed: each layer strips its corresponding header and passes the remaining payload up to the next layer. This is called **decapsulation**. The payload at any given layer is the complete PDU of the layer above, which is why encapsulation is sometimes described as a nesting structure.

#### The OSI and TCP/IP Models

![OSI vs TCP IP](https://lattice-walker.github.io/CipherOps/courses/networks/1illustrations/1OSITCPIP.svg)

The **Open Systems Interconnection** model was developed by the International Organization for Standardization and published in 1984. It defines seven layers, each with a distinct role.

- **Physical.** Responsible for transmitting raw bits over a physical medium. It defines electrical, optical, and mechanical characteristics: voltage levels, cable types, connector shapes, and timing.
- **Data Link.** Provides node-to-node delivery of frames between two directly connected hosts. It handles physical addressing (MAC addresses), error detection (via checksums or CRC), and, in some implementations, flow control. It is commonly subdivided into the Logical Link Control sublayer and the Media Access Control sublayer.
- **Network.** Handles logical addressing and routing, determining the path a packet takes across multiple networks. The Internet Protocol operates at this layer.
- **Transport.** Provides end-to-end communication between processes on different hosts. It manages segmentation, reassembly, error recovery, and flow control. TCP and UDP are the two dominant transport-layer protocols.
- **Session.** Manages the establishment, maintenance, and termination of sessions between applications. It also handles synchronisation and dialog control (half-duplex vs. full-duplex).
- **Presentation.** Responsible for data translation, encoding, compression, and encryption, ensuring that data produced by the application layer of one system can be read by the application layer of another.
- **Application.** The layer closest to the end user. It provides network services directly to applications, such as file transfer, email, and web browsing. Common protocols at this layer include HTTP, SMTP, FTP, and DNS.

In practice, layers 5 and 6 are rarely implemented as distinct layers in modern protocol stacks; their functions are typically absorbed into the application layer or the transport layer.

The **TCP/IP** model, also called the Internet model or the DoD model, was developed alongside the ARPANET project and predates the OSI model. It describes the protocol suite that underlies the modern Internet. It defines four layers.

- **Network Access.** Covers the physical transmission of data and the protocols used to communicate on a single network segment, such as Ethernet or Wi-Fi.
- **Internet.** Handles logical addressing and routing using the Internet Protocol. ICMP and ARP also operate at or near this layer.
- **Transport.** Provides end-to-end communication using TCP or UDP.
- **Application.** Encompasses all protocols that interact directly with user applications, including HTTP, DNS, SMTP, and SSH.

The two models serve different purposes. The OSI model is primarily a reference framework: it provides a conceptual vocabulary for describing network functions and is widely used in documentation, teaching, and troubleshooting. The TCP/IP model is an implementation model: it describes the actual protocol suite deployed on the Internet.

| Dimension | OSI | TCP/IP |
|---|---|---|
| Purpose | Reference model | Implementation model |
| Adoption | Conceptual / pedagogical | Universal (Internet) |

A common point of confusion is that OSI layer numbers are still routinely used to describe TCP/IP behaviour. Referring to a "layer 3 switch" or a "layer 7 firewall" uses OSI terminology to describe devices operating within a TCP/IP network.

#### Cross-Layer Attacks

The layered model assumes that each layer trusts the layer below it to deliver data correctly and that layers do not interfere with one another. Attackers can exploit this assumption in several ways.

**Attacks targeting a single layer.** Many classical attacks are confined to one layer: ARP spoofing operates at layer 2, IP spoofing at layer 3, and TCP session hijacking at layer 4. In each case, the attacker manipulates the PDU of the targeted layer while the other layers remain unaware.

**Cross-layer attacks.** Some attacks deliberately exploit the interaction between layers. A covert channel, for example, may encode information in fields of a lower-layer header (such as the IP identification field) to exfiltrate data in a way that application-layer monitoring cannot detect. Tunnelling attacks embed one protocol inside another, bypassing controls that inspect only a specific layer.

**Protocol confusion.** Certain attacks exploit inconsistencies in how different implementations parse the same PDU. If a firewall and an end host disagree on how to reassemble fragmented IP packets, an attacker can craft fragments that appear benign to the firewall but are reassembled into malicious content by the host. This class of vulnerability, sometimes called an evasion attack, has been documented in intrusion detection systems since the late 1990s.

Understanding the layered model is therefore not only useful for designing networks but also for reasoning about where in the stack a given attack operates and at which layer a countermeasure should be applied.

## 2.2 Physical Layer

The physical layer defines the means by which raw bits are transmitted over a physical medium, covering electrical, optical, and radio signalling, as well as the mechanical and procedural characteristics of the interface between a device and the transmission medium.

### 2.2.1 Waves, Propagation, Bandwidth and Capacity

Signals transmitted over a network are, at the physical level, waves: variations in voltage, light intensity, or electromagnetic field strength that vary over time. A periodic signal can be characterised by its frequency (measured in hertz), its amplitude, and its phase. Most real signals are not purely sinusoidal; [Fourier analysis](https://en.wikipedia.org/wiki/Fourier_analysis) shows that any signal can be decomposed into a sum of sinusoidal components at different frequencies.

The range of frequencies a channel can carry is its bandwidth, measured in hertz. A wider bandwidth allows more information to be transmitted per unit of time. The data rate, measured in bits per second, depends on both the bandwidth and the number of distinguishable signal levels the channel supports.

Two theoretical results bound the maximum data rate of a channel. The Nyquist theorem states that a noiseless channel of bandwidth B can carry at most $2B log_2(V)$ bits per second, where $V$ is the number of discrete signal levels. Shannon's theorem extends this to noisy channels: the maximum data rate is $B log_2(1 + S/N)$, where $S/N$ is the signal-to-noise ratio. This upper bound is called the channel capacity and cannot be exceeded regardless of the encoding scheme used.

Signal propagation speed depends on the medium. In copper cables it is typically 60–70% of the speed of light in a vacuum; in optical fibre it is around 67%. Propagation delay, the time for a signal to travel from sender to receiver, is distinct from transmission delay, which is the time required to place all bits of a frame onto the medium.

#### Noise and Distortion

Several physical phenomena degrade signals in transit.

**Attenuation** is the reduction in signal amplitude over distance. It occurs in all media and is more pronounced at higher frequencies. Amplifiers and repeaters are used to compensate for attenuation on long links.

**Noise** is any unwanted signal superimposed on the transmitted signal. Thermal noise (also called Johnson-Nyquist noise) is present in all conductors at temperatures above absolute zero and sets a fundamental lower bound on the signal-to-noise ratio. Other noise sources include electromagnetic interference from external sources and crosstalk from adjacent conductors.

**Distortion** refers to changes in the shape of a signal caused by the medium. Delay distortion arises because different frequency components of a signal travel at slightly different speeds, causing the signal to spread out over time. This effect, called **dispersion**, is particularly relevant in optical fibre and limits the usable bandwidth over long distances.

**Impulse noise** consists of irregular, high-amplitude spikes caused by external events such as lightning or switching transients. It is a common cause of burst errors in digital transmission.

### 2.2.2 Transmission Media

![Cables comparison](https://lattice-walker.github.io/CipherOps/courses/networks/2illustrations/Cables.png)

#### Coaxial Cable

Coaxial cable consists of a central copper conductor surrounded by a dielectric insulator, a cylindrical conducting shield, and an outer protective jacket. The geometry of the cable confines the electromagnetic field between the inner conductor and the shield, which reduces radiation losses and provides good immunity to external interference.

Coaxial cable was widely used in early Ethernet networks (10BASE5 and 10BASE2) and remains in use for cable television distribution and some broadband access networks. It supports higher bandwidths and longer distances than unshielded twisted pair at equivalent signal levels, but is bulkier and more expensive to install.

#### Twisted Pair Cables

A twisted pair consists of two insulated copper conductors twisted together. Twisting causes the electromagnetic fields of the two conductors to cancel each other, reducing both the emission of interference and the cable's susceptibility to external noise. The number of twists per metre affects performance: more twists per unit length generally improve noise rejection.

Twisted pair cables are classified by category. Category 5e supports up to 1 Gbit/s over 100 metres; Category 6 supports up to 10 Gbit/s over shorter distances; Category 6A extends 10 Gbit/s to 100 metres. Higher categories (7, 8) are used in data centre environments requiring 25 or 40 Gbit/s.

Cables may be unshielded or shielded. Shielded twisted pair adds a foil or braided shield around the pairs, improving noise immunity at the cost of increased bulk and installation complexity.

#### Optical Fibre

Optical fibre transmits data as pulses of light through a glass or plastic core. The core is surrounded by a cladding material with a lower refractive index, causing light to be confined within the core by total internal reflection.

Two main types are in common use. Single-mode fibre has a very narrow core (typically 8–10 micrometres) and carries a single ray of light. It supports very high bandwidths over long distances (tens to hundreds of kilometres) and is used in backbone and long-haul links. Multi-mode fibre has a wider core (50 or 62.5 micrometres) and allows multiple light rays to propagate simultaneously. Modal dispersion, caused by the different path lengths of these rays, limits its usable distance to a few hundred metres, making it suitable for campus and data centre environments.

Optical fibre is immune to electromagnetic interference, does not radiate signals, and supports much higher bandwidths than copper. Its main drawbacks are the cost and skill required for termination and splicing, and its susceptibility to physical damage from bending.

### 2.2.3 Wireless Technologies

Wireless transmission uses electromagnetic waves propagating through free space rather than a guided medium. The behaviour of a wireless link depends on the frequency band used, the antenna characteristics, and the environment. Key impairments include path loss (signal attenuation with distance), multipath fading (caused by reflections arriving at the receiver with different delays and phases), and interference from other transmitters.

![OSI vs TCP IP](https://lattice-walker.github.io/CipherOps/courses/networks/2illustrations/Wireless.svg)

#### Wi-Fi

Wi-Fi is the commercial name for a family of wireless local area network standards defined by IEEE 802.11. The main generations in current use are summarised below.

| Standard | Common name | Frequency bands | Max. theoretical rate |
|---|---|---|---|
| 802.11n | Wi-Fi 4 | 2.4 GHz, 5 GHz | 600 Mbit/s |
| 802.11ac | Wi-Fi 5 | 5 GHz | 3.5 Gbit/s |
| 802.11ax | Wi-Fi 6/6E | 2.4, 5, 6 GHz | 9.6 Gbit/s |
| 802.11be | Wi-Fi 7 | 2.4, 5, 6 GHz | 46 Gbit/s |

Wi-Fi operates in unlicensed frequency bands and uses carrier-sense multiple access with collision avoidance to manage shared access to the medium. The 2.4 GHz band offers better range but is more congested and has fewer non-overlapping channels than the 5 GHz or 6 GHz bands. Higher frequency bands provide more bandwidth but shorter range and poorer penetration through walls.

#### Bluetooth

Bluetooth is a short-range wireless technology defined by the IEEE 802.15.1 standard and maintained by the Bluetooth Special Interest Group. It operates in the 2.4 GHz ISM band and uses frequency-hopping spread spectrum, changing frequency up to 1600 times per second to reduce interference and improve robustness.

Bluetooth is designed for low-power, short-range communication, typically within 10 metres for standard-power devices, though higher-power classes extend this to 100 metres. It is used primarily for peripheral connections (keyboards, headsets, speakers) and personal area networking. Bluetooth Low Energy, introduced in version 4.0, targets applications requiring very low power consumption, such as sensors and wearables, at the cost of reduced throughput.

#### Infrared

Infrared communication uses light in the infrared spectrum (wavelengths between approximately 700 nm and 1 mm) to transmit data over short distances. Because infrared light does not penetrate walls, communication is inherently limited to line-of-sight or near-line-of-sight conditions within a single room.

The Infrared Data Association defined a set of standards for point-to-point infrared communication, supporting data rates from 9.6 kbit/s up to 16 Mbit/s. These were widely used in the 1990s and early 2000s for device synchronisation and file transfer between laptops, PDAs, and mobile phones. Infrared has since been largely displaced by Bluetooth and Wi-Fi in most applications, though it remains in use for remote controls and some industrial sensor applications.

### 2.2.4 Modulation and Multiplexing

Modulation is the process of encoding information onto a carrier signal by varying one or more of its properties: amplitude, frequency, or phase. Digital data must be modulated before transmission over most physical media.

In amplitude modulation, the amplitude of the carrier varies in proportion to the data signal. In frequency modulation, the carrier frequency shifts between discrete values representing different bit patterns. In phase modulation, the phase of the carrier is shifted to encode data. Modern systems typically combine these techniques: quadrature amplitude modulation encodes data by varying both amplitude and phase simultaneously, allowing multiple bits to be carried per symbol. The number of bits per symbol is determined by the number of distinct constellation points; 64-QAM encodes 6 bits per symbol, 256-QAM encodes 8 bits per symbol, and so on.

![Cables comparison](https://lattice-walker.github.io/CipherOps/courses/networks/2illustrations/Multiplexing.svg)

- **Multiplexing** is the technique of combining multiple signals onto a single shared medium or channel.
- **Frequency-division multiplexing** assigns each signal a distinct frequency band within the available spectrum. The signals are transmitted simultaneously and separated at the receiver by filtering. It is used in cable television and radio broadcasting.
- **Time-division multiplexing** divides the channel into time slots and assigns each signal one or more slots in a repeating frame. Each signal transmits only during its allocated slot. It is used in digital telephony networks such as the synchronous digital hierarchy.
- **Wavelength-division multiplexing** is the optical equivalent of frequency-division multiplexing: multiple signals are carried on a single optical fibre, each on a different wavelength of light. Dense wavelength-division multiplexing can combine dozens to hundreds of channels on a single fibre, each at rates of 10, 40, or 100 Gbit/s.
- **Code-division multiplexing** allows multiple signals to share the same frequency band simultaneously by assigning each a unique spreading code. Receivers use the code to extract the intended signal from the combined transmission. It is the basis of several mobile telephony standards, including CDMA2000 and UMTS.
- **Orthogonal frequency-division multiplexing** divides the available bandwidth into a large number of closely spaced subcarriers, each modulated at a low symbol rate. The subcarriers are mathematically orthogonal, which eliminates inter-carrier interference. It is used in Wi-Fi (802.11a and later), 4G LTE, and 5G NR.

### 2.2.5 Data Circuits and Equipment

#### Layer 1 Equipment

Layer 1 devices operate exclusively on the physical signal, with no awareness of the data carried.

A repeater receives an attenuated or distorted signal, reconstructs it, and retransmits it. It extends the usable distance of a cable segment but does not filter or buffer traffic. A [hub](https://lattice-walker.github.io/CipherOps/display_courses/courses.html#article=courses%2Fnetworks%2F1.%20Introduction.md) is a multi-port repeater: any signal received on one port is retransmitted on all other ports. All devices connected to a hub share the same collision domain.

Transceivers convert signals between different physical forms, for example between electrical signals on copper and optical signals on fibre. They are commonly implemented as pluggable modules (SFP, QSFP) to allow the same network equipment to support different media types.

Cables, connectors, and patch panels are passive layer 1 components. Their characteristics (impedance, attenuation, bandwidth) determine the performance limits of the physical link.

#### Layer 2 and Above Equipment

Although these devices are not strictly part of the physical layer, they interact with it directly and are introduced here for context.

- A **bridge** connects two or more network segments and forwards frames based on MAC addresses. Unlike a hub, it maintains a table of known addresses and forwards a frame only to the segment on which the destination address is located, reducing unnecessary traffic. Each port on a bridge defines a separate collision domain.

- A [**switch**](https://lattice-walker.github.io/CipherOps/display_courses/courses.html#article=courses%2Fnetworks%2F1.%20Introduction.md) is a multi-port bridge. Modern switches operate at line rate, maintain per-port MAC address tables, and support features such as VLANs and spanning tree. A switch operating solely on MAC addresses is a layer 2 device; a layer 3 switch additionally performs IP routing between VLANs.

 - A [**router**](https://lattice-walker.github.io/CipherOps/display_courses/courses.html#article=courses%2Fnetworks%2F1.%20Introduction.md) connects networks at layer 3, forwarding packets based on IP addresses and a routing table. It defines the boundary between broadcast domains and is the primary device used to interconnect distinct IP networks.

Devices operating at layer 4 and above, such as [firewalls](https://lattice-walker.github.io/CipherOps/display_courses/courses.html#article=courses%2Fnetworks%2F1.%20Introduction.md) performing stateful inspection or load balancers distributing traffic across servers, are sometimes described using OSI layer numbers to indicate the depth of packet inspection they perform.


## 2.3 Layer 2: Data Link

The data link layer sits between the physical layer and the network layer. It is responsible for transferring frames between two directly connected nodes, handling physical addressing, error detection, and access to the shared medium. On most modern networks, this layer is dominated by Ethernet.

### 2.3.1 Dominant Protocols and Main Functions

Ethernet, defined by the IEEE 802.3 standard, is the dominant data link protocol in wired local area networks. Wi-Fi (IEEE 802.11) performs the equivalent role in wireless networks. Both protocols define frame formats, addressing schemes, and medium access control mechanisms appropriate to their respective physical media.

The data link layer performs several distinct functions.

- **Framing** delimits units of data for transmission. The layer wraps network-layer packets in frames, adding headers and trailers that allow the receiver to identify the start and end of each unit.

- **Physical addressing** identifies nodes on the same network segment using MAC addresses, 48-bit identifiers assigned to each network interface. MAC addresses are written as six pairs of hexadecimal digits (for example, 00:1A:2B:3C:4D:5E). The first three bytes identify the manufacturer and are assigned by the IEEE as an Organizationally Unique Identifier; the last three bytes are assigned by the manufacturer.

- **Error detection** allows the receiver to identify frames corrupted in transit. Ethernet uses a 32-bit cyclic redundancy check appended as a trailer to each frame. Frames that fail the check are silently discarded; retransmission, if required, is the responsibility of higher layers.

- **Medium access control** governs how nodes share access to the physical medium. Early Ethernet used carrier-sense multiple access with collision detection on shared coaxial or hub-based segments. Modern switched Ethernet operates in full-duplex mode on point-to-point links, eliminating collisions entirely.

- **Flow control** prevents a fast sender from overwhelming a slow receiver. At layer 2, this is handled by the IEEE 802.3x pause frame mechanism in full-duplex Ethernet.

### 2.3.2 Ethernet Frame Fields

The standard Ethernet II frame format contains the following fields.

| Field | Size | Description |
|---|---|---|
| Preamble | 7 bytes | Alternating 1/0 pattern used for clock synchronisation |
| Start Frame Delimiter | 1 byte | Marks the end of the preamble (10101011) |
| Destination MAC | 6 bytes | MAC address of the intended recipient |
| Source MAC | 6 bytes | MAC address of the sending interface |
| EtherType / Length | 2 bytes | Identifies the encapsulated protocol (e.g. 0x0800 for IPv4, 0x0806 for ARP, 0x86DD for IPv6) or, for values ≤ 1500, the length of the payload |
| Payload | 46–1500 bytes | Encapsulated network-layer data |
| Frame Check Sequence | 4 bytes | CRC-32 checksum for error detection |

The minimum frame size is 64 bytes (excluding preamble and delimiter); frames shorter than this are called runts and are discarded. The maximum payload of 1500 bytes defines the standard maximum transmission unit for Ethernet. Jumbo frames, supported by some equipment, extend this to 9000 bytes or more, but are not part of the base standard.

The preamble and start frame delimiter are not always shown in protocol analysers, as they are stripped by the network interface before the frame is passed to the operating system.

### 2.3.3 Learning, Switching, Collision and Broadcast Domains

A switch builds and maintains a MAC address table, also called a content-addressable memory table or forwarding table, that maps MAC addresses to the ports on which they have been observed. The learning process works as follows.

When a frame arrives on a port, the switch records the source MAC address and the incoming port number in its table. It then looks up the destination MAC address. If the destination is found in the table, the frame is forwarded only to the corresponding port. If the destination is not found, the frame is flooded: it is sent out on all ports except the one it arrived on. Over time, as devices communicate, the table is populated and flooding becomes less frequent. Entries are removed after an inactivity timeout, typically 300 seconds.

A collision domain is a network segment in which two simultaneous transmissions would collide. Each port on a switch is its own collision domain, since the switch buffers and forwards frames rather than repeating signals. By contrast, all ports on a hub share a single collision domain.

A broadcast domain is the set of devices that receive a frame sent to the broadcast MAC address (FF:FF:FF:FF:FF:FF). All ports on a switch belong to the same broadcast domain by default. Routers do not forward broadcast frames, so each router interface defines the boundary of a broadcast domain. VLANs, discussed in the next section, allow a single switch to be divided into multiple broadcast domains without requiring separate physical hardware.

### 2.3.4 VLANs

![Cables comparison](https://lattice-walker.github.io/CipherOps/courses/networks/2illustrations/Vlan.png)

A virtual local area network is a logical partition of a switched network. Ports assigned to different VLANs cannot exchange frames directly, even if they are on the same physical switch. From the perspective of the devices connected to them, each VLAN behaves as a separate physical network with its own broadcast domain.

VLANs are defined by the IEEE 802.1Q standard. Each VLAN is identified by a 12-bit VLAN identifier, allowing up to 4094 usable VLANs (identifiers 0 and 4095 are reserved).

The 802.1Q standard inserts a 4-byte tag into the Ethernet frame between the source MAC address field and the EtherType field. The tag contains a 16-bit Tag Protocol Identifier (set to 0x8100), a 3-bit priority field used for quality of service, a 1-bit drop-eligible indicator, and the 12-bit VLAN identifier.

- **Data VLANs** carry user-generated traffic and are the most common type. Each data VLAN corresponds to a distinct IP subnet in most network designs.
- **Voice VLANs** are dedicated to IP telephony traffic. Separating voice traffic onto its own VLAN allows quality-of-service policies to be applied consistently and prevents voice traffic from competing with data traffic for bandwidth.
- **Management VLANs** carry traffic used to administer network devices, such as SSH sessions to switches and routers. Isolating management traffic on a dedicated VLAN limits exposure to attacks originating from user segments.
- **Native VLANs** are discussed under trunking below.

#### Trunking and Native VLAN

![Cables comparison](https://lattice-walker.github.io/CipherOps/courses/networks/2illustrations/TrunkingNative.svg)

An access port carries traffic for a single VLAN and connects to end devices. Frames on access ports are untagged: the switch adds or removes the 802.1Q tag internally.

A trunk port carries traffic for multiple VLANs simultaneously and connects switches to other switches or to routers. Frames on trunk ports are tagged with their VLAN identifier so that the receiving device knows which VLAN each frame belongs to.

The native VLAN is a special case on trunk ports: frames belonging to the native VLAN are transmitted untagged. By default on Cisco equipment, the native VLAN is VLAN 1. If the native VLAN is configured differently on the two ends of a trunk link, frames can be forwarded to the wrong VLAN, a condition called a VLAN mismatch. This misconfiguration is also exploited in double-tagging attacks, described in section 2.3.6.

#### Management Protocols

Several protocols assist in managing VLANs across multiple switches.

- **VLAN Trunking Protocol**, a Cisco proprietary protocol, propagates VLAN configuration from a central server switch to all other switches in the same management domain. While it reduces manual configuration effort, it also introduces risk: a switch with a higher configuration revision number can overwrite the VLAN database of all other switches in the domain, which has caused outages in practice.
- **Dynamic Trunking Protocol**, also Cisco proprietary, negotiates whether a link between two switches should operate as a trunk. Ports in auto or desirable mode will negotiate trunking with a compatible peer. Leaving ports in auto mode on access segments is a security concern, as it may allow an attacker to negotiate a trunk and gain access to all VLANs.
- **Multiple Spanning Tree Protocol** (IEEE 802.1s) allows spanning tree instances to be mapped to groups of VLANs, which is relevant when VLANs are in use across a multi-switch topology. This is discussed further in section 2.3.5.

#### Private VLAN

![Cables comparison](https://lattice-walker.github.io/CipherOps/courses/networks/2illustrations/PrivateVlan.svg)

A private VLAN subdivides a standard VLAN into isolated segments while keeping all ports in the same IP subnet. It is defined by IEEE 802.1Q and is commonly used in environments where devices must share a gateway but must not communicate directly with each other, such as hosting environments or demilitarised zones.

A private VLAN uses three port types. Promiscuous ports can communicate with all other ports in the private VLAN, including isolated and community ports; they are typically connected to routers or firewalls. Isolated ports can communicate only with promiscuous ports; they cannot exchange frames with any other isolated or community port. Community ports can communicate with other ports in the same community and with promiscuous ports, but not with isolated ports or other communities.

#### Service VLANs

![Cables comparison](https://lattice-walker.github.io/CipherOps/courses/networks/2illustrations/ServiceVlan.svg)

In provider networks, service VLANs (also called Q-in-Q or 802.1ad) allow a service provider to carry customer 802.1Q-tagged traffic across its own infrastructure without consuming the customer's VLAN identifiers. An outer provider tag (with EtherType 0x88A8) is added to the frame at the provider edge, encapsulating the customer's existing 802.1Q tag. The outer tag is used for switching within the provider network and is removed at the far edge before delivery to the customer.

This mechanism effectively extends the VLAN space to 4094 × 4094 combinations and allows the provider to treat each customer's traffic as a single logical flow regardless of the VLAN structure the customer uses internally.

### 2.3.5 Spanning Tree Protocol

In a network with redundant switch links, loops can form at layer 2. Because Ethernet frames carry no time-to-live field, a frame caught in a loop circulates indefinitely. Broadcast frames loop at increasing rates until they consume all available bandwidth, a condition called a broadcast storm. The MAC address table also becomes unstable, as the switch sees the same source address arriving on different ports in rapid succession.

The Spanning Tree Protocol, defined by IEEE 802.1D, prevents loops by placing redundant links into a blocking state, creating a loop-free logical topology while preserving physical redundancy for failover.

The protocol operates as follows. All switches exchange Bridge Protocol Data Units to elect a root bridge, the switch with the lowest bridge identifier (a combination of a configurable priority value and the switch MAC address). Each non-root switch then determines its root port, the port with the lowest-cost path to the root bridge. On each network segment, one switch is elected as the designated switch and its port on that segment becomes the designated port. All other ports that would create a loop are placed in a blocking state and do not forward frames.

Port states in the original 802.1D protocol are: blocking, listening, learning, and forwarding. Convergence after a topology change can take up to 50 seconds in the original protocol.

- **Rapid Spanning Tree Protocol**, defined by IEEE 802.1w and incorporated into the 2004 revision of 802.1D, reduces convergence time to a few seconds by introducing additional port roles and a negotiation mechanism between adjacent switches.
- **Multiple Spanning Tree Protocol**, defined by IEEE 802.1s, allows multiple spanning tree instances to run simultaneously, each covering a different group of VLANs. This allows traffic to be load-balanced across redundant links by assigning different VLANs to different spanning tree instances with different root bridges.

Spanning tree is also a relevant attack surface. An attacker who can inject Bridge Protocol Data Units with a lower bridge identifier than the current root bridge can cause a topology change, redirecting traffic through a switch under their control. This is discussed in section 2.3.6.

### 2.3.6 Layer 2 Security

#### Attack Taxonomy

- **MAC flooding** exploits the finite size of a switch's MAC address table. An attacker sends a large number of frames with randomly generated source MAC addresses, filling the table. Once the table is full, the switch can no longer learn new addresses and falls back to flooding all frames on all ports, effectively behaving like a hub. The attacker can then capture traffic intended for other hosts.
- **MAC spoofing** involves configuring a network interface to use a MAC address other than the one assigned by the manufacturer. This can be used to impersonate another device, bypass access controls based on MAC address filtering, or hijack sessions.
- **VLAN hopping** allows an attacker to send or receive frames on a VLAN other than the one their port is assigned to.
  - Switch spoofing : the attacker negotiates a trunk link with the switch by sending Dynamic Trunking Protocol messages, gaining access to all VLANs carried on the trunk.
  - Double-tagging : the attacker sends a frame with two 802.1Q tags: an outer tag matching the native VLAN (which the first switch strips without inspection) and an inner tag for the target VLAN. The frame is then forwarded into the target VLAN by the next switch. This attack is unidirectional: the attacker can inject frames into the target VLAN but cannot receive replies.
- **ARP spoofing** (also called ARP poisoning) exploits the stateless nature of the Address Resolution Protocol. An attacker sends unsolicited ARP replies associating their own MAC address with the IP address of another host, such as the default gateway. Hosts that accept these replies update their ARP cache and subsequently send traffic to the attacker rather than the legitimate host. This enables man-in-the-middle interception or denial of service. ARP is examined in more detail in section 2.3.7.
- **Spanning tree attacks** involve injecting Bridge Protocol Data Units to manipulate the spanning tree topology. An attacker who becomes the root bridge can redirect traffic through their own device.
- **DHCP starvation and rogue DHCP** are related attacks. In a starvation attack, the attacker sends a large number of DHCP requests with spoofed MAC addresses, exhausting the server's address pool and preventing legitimate clients from obtaining addresses. A rogue DHCP server then responds to client requests with attacker-controlled configuration, including a malicious default gateway or DNS server.

#### Defense Mechanisms

- **Port security** limits the number of MAC addresses permitted on a switch port and optionally restricts which addresses are allowed. When a violation is detected, the port can be configured to shut down, restrict traffic, or generate an alert. Port security mitigates MAC flooding and some forms of MAC spoofing.
- **Dynamic ARP Inspection** validates ARP packets against a trusted binding table, typically populated by DHCP snooping. ARP replies that do not match a known IP-to-MAC binding are dropped. This prevents ARP spoofing on protected segments.
- **DHCP snooping** classifies switch ports as trusted or untrusted. DHCP server messages received on untrusted ports are dropped, preventing rogue DHCP servers from responding to client requests. The binding table it builds (IP address, MAC address, port, VLAN) is also used by Dynamic ARP Inspection and IP Source Guard.
- **IP Source Guard** filters traffic on untrusted ports based on the DHCP snooping binding table, dropping frames whose source IP address does not match the binding for that port. This prevents IP address spoofing at layer 2.
- **BPDU Guard** disables a port immediately if a Bridge Protocol Data Unit is received on it. It is applied to access ports where no switch should be connected, preventing spanning tree manipulation by unauthorised devices.
- **Native VLAN hardening** involves changing the native VLAN from the default (VLAN 1) to an unused VLAN and explicitly tagging native VLAN traffic on trunk ports where the platform supports it. This eliminates the precondition for double-tagging attacks.
- **Disabling Dynamic Trunking Protocol** on access ports prevents switch spoofing attacks. Ports should be explicitly configured as access ports rather than left in auto or desirable mode.

## 2.4 Layer 3: Network and IP Protocol

The network layer is responsible for logical addressing and the routing of packets across multiple interconnected networks. Unlike the data link layer, which handles communication between directly connected nodes, the network layer provides end-to-end delivery across an arbitrary number of intermediate systems. On the modern Internet, this function is performed almost exclusively by the Internet Protocol.

### 2.4.1 IP Protocol and IPv4 Packet Format

The Internet Protocol version 4, defined in RFC 791 (1981), is a connectionless, best-effort protocol. Connectionless means that each packet is routed independently; best-effort means that the protocol provides no guarantees of delivery, ordering, or integrity. These functions, where required, are delegated to the transport layer.

The IPv4 header has a minimum size of 20 bytes and contains the following fields.

| Field | Size | Description |
|---|---|---|
| Version | 4 bits | IP version (4 for IPv4) |
| IHL | 4 bits | Header length in 32-bit words; minimum value is 5 (20 bytes) |
| DSCP / ECN | 8 bits | Differentiated services code point for quality of service; explicit congestion notification |
| Total Length | 16 bits | Total packet size in bytes, including header and payload; maximum 65 535 bytes |
| Identification | 16 bits | Used to identify fragments belonging to the same original datagram |
| Flags | 3 bits | Bit 0: reserved; Bit 1: Don't Fragment; Bit 2: More Fragments |
| Fragment Offset | 13 bits | Position of this fragment within the original datagram, in units of 8 bytes |
| Time to Live | 8 bits | Decremented by each router; packet is discarded when it reaches zero |
| Protocol | 8 bits | Identifies the encapsulated transport-layer protocol (6 = TCP, 17 = UDP, 1 = ICMP) |
| Header Checksum | 16 bits | Checksum of the header only; recomputed at each hop |
| Source Address | 32 bits | IPv4 address of the sender |
| Destination Address | 32 bits | IPv4 address of the intended recipient |
| Options | 0–40 bytes | Optional fields; present only if IHL > 5 |

The fragmentation fields (Identification, Flags, Fragment Offset) allow a router to split a packet that is too large for the next link's maximum transmission unit. The receiving host reassembles the fragments using the Identification field to group them and the Fragment Offset to order them. Fragmentation is a source of several security vulnerabilities discussed in section 2.4.4.

#### IPv4 Addressing, Subnets and Masks

An IPv4 address is a 32-bit number, conventionally written in dotted-decimal notation as four decimal octets separated by dots (for example, 192.168.1.10). The address space is divided into a network portion and a host portion. The boundary between the two is defined by a subnet mask, a 32-bit value in which all network bits are set to 1 and all host bits are set to 0.

A subnet mask can be written in dotted-decimal notation (255.255.255.0) or in prefix notation, also called CIDR notation, which appends the number of network bits to the address (192.168.1.0/24). The two representations are equivalent.

Given an IP address and a subnet mask, the network address is obtained by a bitwise AND of the two values. The broadcast address of the subnet is obtained by setting all host bits to 1. All addresses between the network address and the broadcast address are usable host addresses.

| Parameter | Example |
|---|---|
| IP address | 192.168.1.10 |
| Subnet mask | 255.255.255.0 (/24) |
| Network address | 192.168.1.0 |
| Broadcast address | 192.168.1.255 |
| Usable host range | 192.168.1.1 – 192.168.1.254 |
| Number of usable hosts | 254 |

Subnetting divides a larger address block into smaller subnets by extending the prefix length. Borrowing one bit from the host portion doubles the number of subnets and halves the number of hosts per subnet. This allows address space to be allocated efficiently to networks of different sizes.

Certain address ranges are reserved for specific purposes by RFC 1918 and other standards.

| Range | Purpose |
|---|---|
| 10.0.0.0/8 | Private use |
| 172.16.0.0/12 | Private use |
| 192.168.0.0/16 | Private use |
| 127.0.0.0/8 | Loopback |
| 169.254.0.0/16 | Link-local (APIPA) |
| 224.0.0.0/4 | Multicast |
| 255.255.255.255/32 | Limited broadcast |

#### Default Gateway

When a host needs to send a packet to a destination outside its own subnet, it cannot deliver the packet directly at layer 2. Instead, it forwards the packet to its default gateway, the IP address of a router interface on the same subnet. The host sends the packet in an Ethernet frame addressed to the router's MAC address (obtained via ARP), and the router then forwards the packet toward the destination.

The default gateway is the host's only exit point to other networks. If the gateway is unreachable, the host can still communicate within its own subnet but cannot reach any external destination.

### 2.4.2 Supporting Protocols

#### ARP and RARP

The Address Resolution Protocol, defined in RFC 826, resolves IPv4 addresses to MAC addresses. When a host needs to send a packet to an IP address on the same subnet and does not know the corresponding MAC address, it broadcasts an ARP request containing the target IP address. The host with that IP address replies with a unicast ARP reply containing its MAC address. The requesting host caches this mapping in its ARP table for a period determined by the operating system (typically a few minutes).

ARP is stateless: hosts accept ARP replies even if they did not send a corresponding request. This property is exploited in ARP spoofing attacks, described in sections 2.3.6 and 2.4.4.

Reverse ARP was an early protocol that allowed a diskless workstation to discover its own IP address by broadcasting its MAC address. It has been superseded by DHCP and is no longer in use.

#### ICMP

The Internet Control Message Protocol, defined in RFC 792, carries error and diagnostic messages for the IP layer. It is encapsulated directly in IP packets with protocol number 1. ICMP messages are identified by a type field and a code field that together specify the nature of the message.

Common ICMP message types include the following.

| Type | Name | Typical use |
|---|---|---|
| 0 | Echo Reply | Response to a ping |
| 3 | Destination Unreachable | Packet could not be delivered; code specifies reason |
| 5 | Redirect | Router instructs host to use a different gateway |
| 8 | Echo Request | Ping request |
| 11 | Time Exceeded | TTL reached zero (used by traceroute) |

ICMP is used by the `ping` utility (types 8 and 0) to test reachability and measure round-trip time, and by `traceroute`, which exploits the Time Exceeded message to discover the path a packet takes to its destination.

ICMP does not authenticate the source of messages. Several attacks exploit this, including ICMP redirect injection and ICMP-based denial of service. These are discussed in section 2.4.4.

#### IGMP

The Internet Group Management Protocol allows hosts to join and leave IP multicast groups and allows routers to track group membership on each interface. It operates between hosts and their directly connected multicast routers.

IGMPv1 (RFC 1112) introduced the basic join mechanism. IGMPv2 (RFC 2236) added an explicit leave message, reducing the time a router waits before stopping multicast forwarding to a segment after the last member leaves. IGMPv3 (RFC 3376) added source filtering, allowing a host to specify that it wishes to receive multicast traffic only from particular source addresses.

Multicast routers use IGMP membership information to decide on which interfaces to forward multicast traffic, avoiding unnecessary replication to segments with no interested receivers.

### 2.4.3 Routing

#### Routing Principles

A router forwards packets based on its routing table, a data structure that maps destination network prefixes to next-hop addresses or outgoing interfaces. When a packet arrives, the router performs a longest prefix match: it selects the routing table entry whose prefix most specifically matches the destination address.

Routes in the routing table can be obtained in three ways. Directly connected routes are added automatically when an interface is configured with an IP address; the router knows it can reach that subnet directly. Static routes are configured manually by an administrator. Dynamic routes are learned from other routers via routing protocols.

When multiple routes to the same destination exist from different sources, the router selects the one with the lowest administrative distance, a value that reflects the trustworthiness of the source. Directly connected routes have an administrative distance of 0, static routes typically 1, and dynamic routing protocols have higher values that vary by protocol and implementation.

#### Autonomous Systems and Routing Protocols

The Internet is divided into autonomous systems, each a collection of IP networks under a single administrative authority with a common routing policy. Each autonomous system is identified by a 16-bit or 32-bit Autonomous System Number, assigned by regional Internet registries.

Routing protocols are classified by where they operate. Interior gateway protocols exchange routing information within a single autonomous system. Exterior gateway protocols exchange routing information between autonomous systems.

Routing algorithms fall into two main categories. Distance-vector protocols have each router advertise its routing table to its neighbours; routers compute the best path based on the information received, without a complete view of the network topology. Link-state protocols have each router flood information about its directly connected links to all routers in the network; each router then independently computes the shortest path tree using Dijkstra's algorithm.

#### RIP

The Routing Information Protocol is a distance-vector interior gateway protocol defined in RFC 2453 (RIPv2). It uses hop count as its sole metric, with a maximum of 15 hops; a hop count of 16 is treated as infinity and indicates an unreachable destination. Routers broadcast their full routing table to neighbours every 30 seconds.

RIP is simple to configure but converges slowly and does not scale beyond small networks. The 15-hop limit makes it unsuitable for large or complex topologies. It has been largely replaced by OSPF and EIGRP in production environments.

#### OSPF

The Open Shortest Path First protocol is a link-state interior gateway protocol defined by RFC 2328 (OSPFv2 for IPv4) and RFC 5340 (OSPFv3 for IPv6). Each router maintains a link-state database describing the complete topology of the network and runs Dijkstra's algorithm to compute the shortest path tree rooted at itself.

OSPF uses the concept of areas to limit the scope of topology information. All areas must connect to the backbone area (area 0). Routers within an area have a complete view of that area's topology but see only summary information about other areas. This hierarchical structure reduces the size of the link-state database and the computational load on routers in large networks.

OSPF uses cost as its metric, typically derived from interface bandwidth. It converges faster than RIP, supports variable-length subnet masking, and authenticates routing updates. It is the most widely deployed interior gateway protocol in enterprise and service provider networks.

#### BGP

The Border Gateway Protocol, defined in RFC 4271, is the exterior gateway protocol of the Internet. It is a path-vector protocol: each route advertisement carries the full sequence of autonomous systems the route has traversed, allowing routers to detect and avoid loops and to apply policy based on the path.

BGP sessions are established over TCP on port 179. A session between routers in different autonomous systems is called an external BGP session; a session between routers within the same autonomous system is called an internal BGP session.

BGP selects routes based on a sequence of attributes rather than a single metric. The most commonly manipulated attributes include the AS path length, the local preference (used within an autonomous system to prefer one exit point over another), and the multi-exit discriminator (used to suggest a preferred entry point to a neighbouring autonomous system).

BGP carries the full Internet routing table, which exceeded 900 000 prefixes in 2024. Route selection and policy configuration in BGP are complex, and misconfigurations have historically caused significant outages and route leaks affecting large portions of the Internet.

### 2.4.4 Layer 3 Security

#### Sources of Vulnerabilities

Several structural properties of IPv4 and its supporting protocols create security weaknesses.

- **IP spoofing.** IPv4 does not authenticate the source address field. An attacker can send packets with an arbitrary source address, impersonating another host or concealing their origin. Spoofed packets are used in reflection and amplification attacks, where the attacker sends requests to open servers with the victim's address as the source; the servers send their (often much larger) replies to the victim.
- **Fragmentation attacks.** The IP fragmentation mechanism can be abused in several ways. Overlapping fragments, where two fragments claim to occupy the same offset range but carry different data, can cause ambiguity in reassembly. Different operating systems historically resolved this ambiguity differently, allowing attackers to craft fragments that appear benign to a firewall but reassemble into malicious content at the destination. The Teardrop attack sent malformed fragments with overlapping offsets that caused some operating systems to crash during reassembly.
- **ICMP attacks.** Because ICMP messages are not authenticated, an attacker can inject ICMP Redirect messages to alter a host's routing table, directing traffic through an attacker-controlled path. ICMP Destination Unreachable messages with code 4 (fragmentation needed) can be used to manipulate path MTU discovery. Smurf attacks, now largely mitigated by network filtering, used ICMP echo requests sent to broadcast addresses with a spoofed source address to generate large volumes of traffic directed at a victim.
- **Routing protocol attacks.** Interior gateway protocols that do not authenticate their updates are vulnerable to route injection. An attacker who can send OSPF or RIP messages can advertise false routes, redirecting traffic or causing a denial of service. BGP, which relies on TCP sessions and optional authentication, is vulnerable to route hijacking: an autonomous system that announces a prefix it does not legitimately hold can attract traffic intended for the legitimate holder, either accidentally (as in the 2008 Pakistan Telecom incident) or deliberately.
- **TTL manipulation.** The time-to-live field is decremented by routers and is not authenticated. An attacker can send packets with a very low TTL to probe network topology or to cause packets to expire at a specific point in the network.

#### Security Recommendations

- **Ingress and egress filtering (BCP 38).** Routers at the boundary of a network should drop packets whose source address does not belong to the address space legitimately assigned to that network. Ingress filtering prevents spoofed packets from entering the network from outside; egress filtering prevents spoofed packets from leaving. This practice is described in RFC 2827 and reduces the effectiveness of reflection and amplification attacks.
- **Disabling IP-directed broadcasts.** Routers should not forward packets addressed to a subnet broadcast address, eliminating the amplification step in Smurf-style attacks. This is the default behaviour on most modern routers.
- **ICMP filtering.** Certain ICMP message types, particularly Redirect (type 5), should be filtered at network boundaries. Echo requests (type 8) are often rate-limited or blocked on infrastructure interfaces, though blocking them entirely impairs legitimate diagnostic use.
- **Routing protocol authentication.** OSPF supports MD5 and SHA-based authentication of routing updates. BGP sessions should use TCP MD5 authentication (RFC 2385) or, preferably, the TCP Authentication Option (RFC 5925). Static route filters and prefix lists should be used to limit the prefixes a router will accept from a peer.
- **Route Origin Authorisation and RPKI.** The Resource Public Key Infrastructure allows autonomous system operators to publish cryptographically signed statements (Route Origin Authorisations) asserting which autonomous systems are authorised to originate specific prefixes. Routers that perform RPKI validation can reject BGP announcements that conflict with published authorisations, mitigating prefix hijacking.
- **Fragmentation handling.** Firewalls and intrusion prevention systems should reassemble fragments before inspection, or drop fragmented packets on segments where fragmentation is not expected. The Don't Fragment bit should be set on traffic where path MTU discovery is in use.

## 2.5 Layer 4: Transport

The transport layer provides end-to-end communication between processes running on different hosts. While the network layer delivers packets between hosts, the transport layer extends this to deliver data between specific applications, identified by port numbers. The two dominant transport-layer protocols are TCP, which provides reliable, ordered, connection-oriented delivery, and UDP, which provides lightweight, connectionless delivery with no guarantees.

### 2.5.1 TCP

#### Characteristics

The Transmission Control Protocol, defined in RFC 793 (1981) and updated by RFC 9293 (2022), provides the following properties.

- **Connection-oriented.** Before data is exchanged, a connection is established between the two endpoints through a handshake procedure. The connection is explicitly terminated when communication is complete.
- **Reliable delivery.** Every byte of data is acknowledged by the receiver. If an acknowledgement is not received within a timeout period, the sender retransmits the data.
- **Ordered delivery.** TCP assigns a sequence number to each byte. The receiver uses these numbers to reorder segments that arrive out of sequence and to detect gaps.
- **Flow control.** The receiver advertises a window size indicating how much data it is prepared to accept. The sender limits the amount of unacknowledged data in flight to this value.
- **Congestion control.** TCP adjusts its sending rate in response to network congestion, using mechanisms such as slow start, congestion avoidance, fast retransmit, and fast recovery.
- **Full-duplex.** Data can flow in both directions simultaneously on a single connection.

#### Segment Format

A TCP segment consists of a header of at least 20 bytes followed by a payload.

| Field | Size | Description |
|---|---|---|
| Source Port | 16 bits | Port number of the sending process |
| Destination Port | 16 bits | Port number of the receiving process |
| Sequence Number | 32 bits | Byte offset of the first byte of payload in this segment |
| Acknowledgement Number | 32 bits | Next byte the sender expects to receive (valid only if ACK flag is set) |
| Data Offset | 4 bits | Header length in 32-bit words; minimum value is 5 (20 bytes) |
| Reserved | 3 bits | Must be zero |
| Control Flags | 9 bits | URG, ACK, PSH, RST, SYN, FIN (and ECN-related flags CWR, ECE, NS) |
| Window Size | 16 bits | Number of bytes the receiver is willing to accept |
| Checksum | 16 bits | Covers the header, payload, and a pseudo-header derived from the IP header |
| Urgent Pointer | 16 bits | Offset to urgent data (valid only if URG flag is set) |
| Options | 0–40 bytes | Optional fields; present only if Data Offset > 5 |

The most commonly observed control flags are SYN (synchronise, used to initiate a connection), ACK (acknowledgement), FIN (finish, used to close a connection gracefully), and RST (reset, used to abort a connection abruptly).

- **Connection establishment** uses a three-way handshake. The client sends a SYN segment with a randomly chosen initial sequence number. The server responds with a SYN-ACK, acknowledging the client's sequence number and advertising its own. The client completes the handshake with an ACK. After this exchange, both sides have agreed on initial sequence numbers and the connection is established.
- **Connection termination** normally uses a four-way exchange. Either side sends a FIN to indicate it has no more data to send. The other side acknowledges the FIN, then sends its own FIN when it is also done, which is acknowledged in turn. Because each direction is closed independently, it is possible for one side to stop sending while the other continues, a state called half-close.

#### Flow Control and Reliability

TCP reliability is based on the sliding window mechanism. The sender maintains a window of bytes that have been sent but not yet acknowledged. The size of this window is bounded by the receiver's advertised window (flow control) and by the congestion window maintained by the sender (congestion control).

Each segment carries a sequence number. The receiver sends an acknowledgement containing the sequence number of the next byte it expects. If a segment is lost, the receiver continues to acknowledge the last in-order byte received. The sender, observing that acknowledgements are not advancing, retransmits the missing segment after a timeout or, in fast retransmit, after receiving three duplicate acknowledgements.

The maximum segment size is negotiated during the handshake via a TCP option. It specifies the largest payload the sender is willing to receive and is typically derived from the path MTU to avoid fragmentation.

Congestion control begins with slow start: the congestion window starts small and doubles with each round trip until a threshold is reached or a loss event occurs. After the threshold, the window grows linearly in the congestion avoidance phase. On detecting loss, the sender reduces its congestion window and resumes growth more conservatively.

#### TCP-Related Attacks

- **SYN flooding.** An attacker sends a large number of SYN segments with spoofed source addresses. The server allocates state for each half-open connection and sends SYN-ACK replies that are never acknowledged. The server's connection table fills up, preventing it from accepting legitimate connections. The standard mitigation is SYN cookies: the server encodes connection state in the initial sequence number of the SYN-ACK rather than allocating a table entry, deferring state allocation until the ACK is received.
- **TCP session hijacking.** If an attacker can observe or predict the sequence numbers of an established connection, they can inject segments that appear to belong to that connection. This allows them to inject data or terminate the connection with a RST segment. Sequence number randomisation, required by RFC 6528, makes prediction significantly harder.
- **RST injection.** An attacker sends a RST segment with a plausible sequence number to one or both endpoints of a connection, causing it to be abruptly terminated. This technique has been used to disrupt peer-to-peer connections and, notably, was employed by the Great Firewall of China to terminate connections to censored content.
- **Man-in-the-middle attacks.** An attacker positioned between two communicating hosts can intercept, modify, or replay TCP segments. At layer 4, this requires the attacker to maintain correct sequence numbers for both directions. In practice, man-in-the-middle attacks at this layer are typically enabled by lower-layer compromises such as ARP spoofing.
- **Idle scanning.** A port scanning technique that exploits the predictable IP identification field of a third host (the zombie) to infer whether ports on a target are open, without sending any packets directly from the attacker's address.

### 2.5.2 Reconstructing a TCP Session with Wireshark

Wireshark can reassemble the byte stream of a TCP connection from a packet capture and display the application-layer data exchanged. The Follow TCP Stream function groups all segments belonging to a connection, identified by the four-tuple of source address, source port, destination address, and destination port, and presents the reassembled payload in both directions. This allows an analyst to read the content of unencrypted sessions, observe the handshake and termination sequence, and identify anomalies such as retransmissions, out-of-order segments, or unexpected RST segments. The following chapter covers this technique in detail alongside other capture and analysis methods.

### 2.5.3 UDP

#### Characteristics

The User Datagram Protocol, defined in RFC 768 (1980), is a connectionless, unreliable transport protocol. It adds only port-based multiplexing and an optional checksum to the IP service. There is no handshake, no acknowledgement, no retransmission, and no flow or congestion control.

UDP is appropriate for applications that tolerate or manage loss themselves, require low latency, or carry short transactions where the overhead of TCP connection establishment is disproportionate. Typical uses include DNS queries, DHCP, streaming media, online gaming, and VoIP. Several modern protocols, including QUIC (which underlies HTTP/3), implement their own reliability and congestion control on top of UDP.

#### Segment Format

A UDP datagram has a fixed 8-byte header.

| Field | Size | Description |
|---|---|---|
| Source Port | 16 bits | Port number of the sending process (optional; may be set to 0 if no reply is expected) |
| Destination Port | 16 bits | Port number of the receiving process |
| Length | 16 bits | Total length of the datagram in bytes, including the header |
| Checksum | 16 bits | Covers the header, payload, and a pseudo-header derived from the IP header; optional in IPv4, mandatory in IPv6 |

The simplicity of the UDP header means that the protocol imposes minimal processing overhead. The maximum payload size is bounded by the IP maximum datagram size of 65 535 bytes minus the IP and UDP headers, though in practice payloads are kept below the path MTU to avoid fragmentation.

#### Common UDP Attacks

- **UDP flooding.** An attacker sends a large volume of UDP datagrams to random ports on a target host. The host, finding no application listening on each port, generates ICMP Destination Unreachable replies, consuming both inbound and outbound bandwidth. At sufficient volume, this exhausts the target's network capacity.
- **Amplification attacks.** Many UDP-based protocols respond to small requests with much larger replies. An attacker sends requests with a spoofed source address set to the victim's address; the servers send their large replies to the victim. Protocols historically exploited for amplification include DNS (amplification factor up to approximately 70×), NTP (up to approximately 556× using the monlist command), SSDP, memcached (up to approximately 51 000×), and CLDAP. Mitigation requires source address validation at the network level (BCP 38) and rate limiting or disabling of amplifiable services.
- **Fragmentation attacks.** Because UDP has no built-in reassembly, large UDP datagrams that exceed the path MTU are fragmented at the IP layer. Attackers can send overlapping or malformed fragments to exploit weaknesses in reassembly code, as described in section 2.4.4.

### 2.5.4 Ports, Scanning and Filtering

#### Port Concepts and IANA Registries

A port is a 16-bit unsigned integer (range 0–65 535) that identifies a specific process or service on a host. The combination of an IP address and a port number is called a socket. A TCP or UDP connection is identified by a four-tuple: source IP address, source port, destination IP address, and destination port.

The Internet Assigned Numbers Authority divides the port number space into three ranges.

| Range | Name | Description |
|---|---|---|
| 0–1023 | Well-known ports | Assigned to standard services; require elevated privileges to bind on most operating systems |
| 1024–49151 | Registered ports | Assigned to specific applications on request; do not require elevated privileges |
| 49152–65535 | Dynamic / ephemeral ports | Used as temporary source ports by clients; not assigned to specific services |

Commonly referenced well-known port assignments include port 22 (SSH), 25 (SMTP), 53 (DNS), 80 (HTTP), 443 (HTTPS), and 3389 (RDP). The full registry is maintained by IANA and published at iana.org.

#### Port Scanning and Vulnerability Exploitation

Port scanning is the process of probing a host or range of hosts to determine which ports are open, and therefore which services may be running. It is a standard step in both legitimate network auditing and in attacker reconnaissance.

The most widely used port scanner is Nmap. It supports several scanning techniques.

- **TCP connect scan.** The scanner completes a full three-way handshake with each target port. An open port completes the handshake; a closed port responds with RST. This technique is reliable but easily logged.
- **SYN scan (half-open scan).** The scanner sends a SYN and waits for a response. An open port replies with SYN-ACK; the scanner immediately sends RST rather than completing the handshake. Because the connection is never fully established, it may not appear in application logs. This requires raw socket access and therefore elevated privileges.
- **UDP scan.** The scanner sends a UDP datagram to each port. A closed port typically generates an ICMP Destination Unreachable reply; an open port either responds with application data or produces no reply. UDP scanning is slower than TCP scanning because of ICMP rate limiting.
- **FIN, NULL, and Xmas scans.** These send segments with unusual flag combinations. On RFC-compliant systems, a closed port responds with RST and an open port produces no response. Some firewalls that block SYN packets pass these segments, making the technique useful for firewall evasion in certain configurations.
- **Version detection and OS fingerprinting.** Nmap can probe open ports to identify the application and version running, and can infer the operating system from characteristics of the TCP/IP stack such as initial window size, TTL, and option ordering.

Once open ports are identified, an attacker maps them to known services and searches for applicable vulnerabilities. Databases such as the Common Vulnerabilities and Exposures registry and the Exploit Database catalogue known weaknesses by software version. Automated exploitation frameworks such as Metasploit can combine scanning results with exploit modules to attempt compromise with minimal manual effort.

#### Flow Monitoring

Flow monitoring collects summary statistics about network traffic without capturing full packet payloads. A flow is typically defined by the five-tuple: source IP address, source port, destination IP address, destination port, and protocol. For each flow, a collector records metrics such as byte count, packet count, start time, and duration.

The dominant flow export protocols are NetFlow (developed by Cisco, defined in RFC 3954 for version 9), IPFIX (the IETF standardisation of NetFlow version 10, defined in RFC 7011), and sFlow, which uses statistical packet sampling rather than per-flow accounting.

Flow data is used for capacity planning, billing, and security analysis. In a security context, flow records can reveal port scans (a single source contacting many destinations on the same port), data exfiltration (large outbound flows to unusual destinations), and botnet command-and-control traffic (periodic small flows to fixed external addresses). Because flow data does not contain payload content, it can be retained and analysed without the legal and privacy constraints that apply to full packet capture.

#### Filtering

Packet filtering controls which packets are permitted to pass through a network device based on header fields. Filters are applied at routers, firewalls, and host-based firewall software.

- A **stateless filter** (also called an access control list in router terminology) evaluates each packet independently against a set of rules. Rules typically match on source and destination IP address, protocol, and source and destination port. Stateless filters are fast and simple but cannot distinguish between the first packet of a new connection and a packet belonging to an established session.
- A **stateful filter** tracks the state of TCP connections and UDP pseudo-sessions. It permits return traffic automatically for established connections without requiring explicit rules for each direction. Stateful inspection also allows the firewall to detect and block certain anomalous packets, such as a SYN-ACK arriving without a prior SYN.
- **Deep packet inspection** extends filtering to the payload, allowing rules based on application-layer content such as protocol signatures, URLs, or file types. It is used in next-generation firewalls and intrusion prevention systems.

Port-based filtering is a basic but widely deployed security control. Common practices include blocking inbound connections to all ports except those hosting intentionally exposed services, blocking outbound connections to ports associated with known malicious activity, and rate-limiting ICMP and UDP traffic to reduce the impact of flooding and amplification attacks.

## 2.6 Application Protocols and Network Services

Application-layer protocols rely on the transport layer to carry their messages between hosts. This section covers two protocols that underpin almost all network communication: DHCP, which assigns IP configuration to hosts automatically, and DNS, which maps human-readable names to IP addresses. Both are frequent targets of attack because compromising either one can redirect or intercept traffic at scale.

### 2.6.1 DHCP

The Dynamic Host Configuration Protocol, defined in RFC 2131, allows a host to obtain an IP address, subnet mask, default gateway, DNS server addresses, and other configuration parameters automatically when it connects to a network. It operates over UDP, using port 67 on the server and port 68 on the client.

#### How DHCP Works

The address assignment process follows a four-message exchange, commonly abbreviated as DORA.

- **Discover.** The client, which has no IP address yet, broadcasts a DHCPDISCOVER message to 255.255.255.255. The source address is 0.0.0.0. All DHCP servers on the segment receive the broadcast.
- **Offer.** One or more servers respond with a DHCPOFFER, proposing an IP address and configuration parameters. The offer is sent to the broadcast address (since the client has no address yet) and includes the client's MAC address to identify the intended recipient.
- **Request.** The client selects one offer and broadcasts a DHCPREQUEST, identifying the chosen server and the offered address. Broadcasting the request informs all servers, including those whose offers were not accepted, so they can release the reserved addresses.
- **Acknowledge.** The selected server sends a DHCPACK confirming the assignment. The client configures its interface with the provided parameters.

The assigned address is leased for a finite duration. Before the lease expires, the client sends a DHCPREQUEST to renew it. If the server is unreachable, the client attempts to contact any server. If no renewal is possible, the client must release the address and restart the DORA process.

DHCP relay agents allow a single DHCP server to serve multiple subnets. A relay agent on each subnet intercepts broadcast DHCP messages and forwards them as unicast to the server, inserting the subnet information so the server can assign an address from the correct pool.

#### Attacks on DHCP

- **DHCP starvation.** An attacker sends a large number of DHCPDISCOVER messages with spoofed MAC addresses, causing the server to allocate addresses from its pool until it is exhausted. Legitimate clients are then unable to obtain an address. This is often a precursor to deploying a rogue DHCP server.
- **Rogue DHCP server.** An attacker operates an unauthorised DHCP server on the network. Clients that receive an offer from the rogue server before the legitimate server are configured with attacker-controlled parameters, typically a malicious default gateway or DNS server. This enables man-in-the-middle interception or DNS-based redirection of all traffic from affected clients.
- **DHCP-based man-in-the-middle.** By advertising itself as the default gateway in DHCP responses, the attacker receives all traffic from affected clients, forwards it to the legitimate gateway, and can inspect or modify it in transit.

#### Countermeasures

- **DHCP snooping**, described in section 2.3.6, is the primary layer 2 defence. It classifies switch ports as trusted or untrusted and drops DHCP server messages arriving on untrusted ports, preventing rogue servers from responding to clients.
- **Port security** limits the number of MAC addresses permitted on a port, reducing the effectiveness of starvation attacks that rely on generating large numbers of distinct MAC addresses.
- **Static DHCP assignments** (also called DHCP reservations) bind specific MAC addresses to fixed IP addresses. In environments where all devices are known, this eliminates the pool of available dynamic addresses and makes starvation attacks ineffective.
- **DHCPv6 and SLAAC** introduce different mechanisms for IPv6 address assignment. Stateless Address Autoconfiguration allows hosts to configure their own addresses from a router-advertised prefix without a server. DHCPv6 provides stateful assignment analogous to DHCPv4. Both are subject to rogue router and rogue server attacks, mitigated by RA Guard and DHCPv6 Guard on supporting switches.

### 2.6.2 DNS

The Domain Name System, defined in RFC 1034 and RFC 1035, is a hierarchical, distributed database that maps domain names to IP addresses and other resource records. It operates primarily over UDP on port 53, falling back to TCP for responses that exceed 512 bytes or for zone transfers (a limit extended to 4096 bytes by EDNS0, defined in RFC 6891).

#### How DNS Works

The DNS namespace is organised as a tree. The root is represented by a single dot. Below the root are top-level domains such as com, org, and country-code domains such as fr and uk. Each node in the tree is managed by an authoritative name server responsible for that zone.

Resolution proceeds as follows. A client application calls the operating system's resolver, which queries a recursive resolver (also called a recursive nameserver or full-service resolver), typically provided by the ISP or a public service such as 8.8.8.8 or 1.1.1.1. If the recursive resolver does not have the answer cached, it performs iterative resolution.

The recursive resolver first queries a root nameserver, which responds with a referral to the nameservers responsible for the relevant top-level domain. The resolver then queries the top-level domain nameserver, which refers it to the authoritative nameserver for the second-level domain. The authoritative nameserver returns the requested record. The recursive resolver caches the result for the duration specified by the record's time-to-live value and returns the answer to the client.

Common DNS record types include the following.

| Type | Description |
|---|---|
| A | Maps a domain name to an IPv4 address |
| AAAA | Maps a domain name to an IPv6 address |
| CNAME | Canonical name; aliases one name to another |
| MX | Mail exchanger; identifies the mail server for a domain |
| NS | Identifies the authoritative nameservers for a zone |
| PTR | Reverse lookup; maps an IP address to a domain name |
| SOA | Start of Authority; contains administrative information about a zone |
| TXT | Arbitrary text; used for SPF, DKIM, and domain verification records |
| SRV | Service locator; specifies host and port for a service |

DNS was designed without authentication. A resolver has no way to verify that a response came from the legitimate authoritative server or that it has not been modified in transit. DNSSEC, defined in RFC 4033 through RFC 4035, addresses this by adding cryptographic signatures to DNS records, allowing resolvers to verify the integrity and authenticity of responses. Adoption of DNSSEC remains incomplete across both authoritative zones and recursive resolvers.

#### DNS as a Strategic Centralisation Point

DNS is a dependency for almost all network communication. A host that cannot resolve names cannot reach services by their domain names, even if the underlying network is functional. This makes DNS infrastructure a high-value target: disrupting or subverting DNS can affect large numbers of users simultaneously.

Recursive resolvers, in particular, represent a point of centralisation. A small number of public resolvers (operated by Google, Cloudflare, and others) handle a substantial fraction of global DNS queries. An operator of a recursive resolver can observe the query patterns of all clients using it, and can influence resolution by returning modified or filtered responses.

DNS is also used as a control channel by malware. Because DNS traffic is rarely blocked and recursive resolvers are trusted, attackers use DNS queries and responses to communicate with command-and-control infrastructure (DNS tunnelling) or to locate it (fast-flux DNS, domain generation algorithms).

#### Attacks on DNS

- **DNS cache poisoning.** An attacker attempts to insert a forged record into a recursive resolver's cache. If successful, all clients using that resolver receive the forged answer for the duration of the record's time-to-live. The Kaminsky attack, disclosed in 2008, demonstrated that the 16-bit DNS transaction identifier alone provided insufficient protection: an attacker could send a large number of forged responses with guessed transaction identifiers, and had a high probability of success before the legitimate response arrived. The immediate mitigation was source port randomisation, which adds approximately 16 bits of additional entropy. DNSSEC provides a cryptographic solution but requires deployment on both the authoritative zone and the resolver.
- **DNS spoofing.** More broadly, any attack that causes a resolver or client to accept a forged DNS response. On a local network, an attacker who has performed ARP spoofing can intercept DNS queries and return forged responses directly, without needing to poison a cache.
- **DNS amplification.** DNS is a common vector for UDP amplification attacks. An attacker sends queries with a spoofed source address to open recursive resolvers, requesting record types that produce large responses (such as ANY or DNSSEC-signed zones). Amplification factors of 28–70× are typical. Mitigation requires restricting recursive resolution to authorised clients and implementing BCP 38 source address validation.
- **DNS tunnelling.** Data is encoded in DNS query and response fields (typically subdomains of an attacker-controlled zone) to create a covert communication channel. Tools such as Iodine and dnscat2 implement this technique. Detection relies on monitoring for anomalous query patterns: unusually long subdomains, high query rates to a single domain, or non-standard record types.
- **NXDOMAIN attacks.** An attacker floods a resolver with queries for non-existent domain names, forcing it to perform full iterative resolution for each query and exhausting its processing capacity.
- **DNS hijacking.** An attacker modifies the DNS configuration of a host, router, or registrar account to redirect queries to a malicious resolver. Registrar-level hijacking, where an attacker gains access to a domain's registrar account and changes its NS records, can redirect all traffic for a domain globally.
- **Fast-flux DNS.** Malware operators rapidly rotate the IP addresses associated with a domain name, using short time-to-live values, to make takedown of command-and-control infrastructure difficult. A single domain may resolve to hundreds of different addresses within a short period.
- **Domain generation algorithms.** Malware generates a large number of pseudo-random domain names using a deterministic algorithm seeded with a value such as the current date. The attacker registers only a small subset of these domains; the malware queries each generated name until it finds one that resolves. This makes blocking by domain name impractical without knowledge of the algorithm.

#### DNS and IPv6

DNS supports IPv6 through the AAAA record type, which maps a domain name to a 128-bit IPv6 address. Reverse lookups for IPv6 addresses use the ip6.arpa zone. The resolution process is identical to IPv4.

In dual-stack environments, a host may receive both A and AAAA records for a name. The selection between IPv4 and IPv6 is governed by the Happy Eyeballs algorithm (RFC 8305), which attempts both in parallel and uses whichever connection succeeds first, with a slight preference for IPv6.

DNS64, defined in RFC 6147, is used in IPv6-only networks to synthesise AAAA records for IPv4-only destinations, allowing IPv6 clients to reach them via a NAT64 gateway. This introduces additional complexity and potential for manipulation if the DNS64 resolver is not trusted.
