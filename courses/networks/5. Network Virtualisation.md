#  Network Virtualisation and Carrier Networks

## 1 VXLAN

![VXLAN](https://lattice-walker.github.io/CipherOps/courses/networks/5illustrations/VXLAN.svg)

A Virtual eXtensible LAN, is a network virtualisation protocol that encapsulates Layer 2 Ethernet frames within UDP packets, allowing them to be transported across an IP network. The protocol was standardised by the Internet Engineering Task Force in RFC 7348, published in 2014.

VXLAN was developed to address a structural limitation of the 802.1Q VLAN tagging standard. The 802.1Q header reserves 12 bits for the VLAN identifier, which allows for 4096 possible values. Two of these are reserved for internal use, leaving 4094 usable VLANs. In large multi-tenant environments such as public cloud data centres, this number is insufficient to isolate the networks of individual customers or workloads at scale.

VXLAN addresses this limitation through the VXLAN Network Identifier, a 24-bit field that allows for approximately 16 million distinct logical network segments. Each VXLAN segment behaves as an independent Layer 2 domain, even though the underlying transport is a routed IP network.

The encapsulation process wraps the original Ethernet frame inside a VXLAN header, which is then placed inside a UDP datagram, an IP packet, and an outer Ethernet frame. The resulting structure allows Layer 2 traffic to traverse a Layer 3 network transparently. This construction is generally described as an overlay network running over an IP underlay: the overlay carries the logical, tenant-facing topology, while the underlay provides IP reachability between the devices performing encapsulation.

Typical use cases for VXLAN include data centre virtualisation, multi-tenant cloud environments where customer networks must remain isolated from one another, and workload mobility, where virtual machines are moved between physical hosts without requiring changes to their IP or MAC addresses.

Because VXLAN adds a VXLAN header, a UDP header, and an outer IP header to each encapsulated frame, the resulting packet is larger than the original Ethernet frame, typically by around 50 bytes. If the underlay network is not configured to accommodate this additional overhead, packets exceeding the standard 1500-byte Maximum Transmission Unit will be fragmented, which can affect performance. For this reason, underlay networks carrying VXLAN traffic are commonly configured with jumbo frame support.

### 1.1 VXLAN Tunnel Endpoint

The device or software component responsible for performing VXLAN encapsulation and decapsulation is called a VXLAN Tunnel Endpoint, generally abbreviated as VTEP. A VTEP can be implemented in hardware, typically in top-of-rack switches, or in software, typically within a hypervisor's virtual switch. Each VTEP is identified in the underlay network by an IP address, which is used as the source or destination address for encapsulated traffic.

In the absence of a dedicated control plane, VTEPs discover the location of destination hosts through a flood-and-learn mechanism. Broadcast, unknown unicast, and multicast traffic, collectively referred to as BUM traffic, is flooded to all VTEPs participating in a given VXLAN segment. Each VTEP observes the source information in this flooded traffic and builds a mapping between MAC addresses and remote VTEP IP addresses, in a manner analogous to traditional Ethernet switch learning.

Flood-and-learn has recognised scalability limitations. It depends on either multicast support in the underlay network, which is not always available or desirable, or on ingress replication, where the ingress VTEP sends a separate copy of BUM traffic to every other VTEP, which increases load as the number of VTEPs grows.

The choice between hardware and software VTEPs involves trade-offs in throughput and offload capability. Hardware VTEPs, implemented in switching silicon, generally support higher packet rates through dedicated encapsulation and decapsulation logic. Software VTEPs, implemented in a hypervisor, offer flexibility but may rely on the host CPU for encapsulation unless hardware offload features are available on the network interface card.

VTEPs also play a role in workload mobility. Because the overlay separates the logical network from the physical underlay, a virtual machine can be migrated from one physical host to another, and therefore from one VTEP to another, without changing its IP or MAC address. The mapping maintained by the VTEPs, whether learned through flooding or distributed through a control plane, is updated to reflect the new location.

### 1.2 BGP EVPN

Ethernet VPN is a control plane that uses the Border Gateway Protocol to distribute MAC address and IP address reachability information between VTEPs. It was originally standardised in RFC 7432 and later extended for use with VXLAN encapsulation in RFC 8365.

BGP EVPN replaces the flood-and-learn model with a control-plane-driven approach. Instead of discovering remote MAC addresses through data-plane flooding, VTEPs advertise the MAC and IP addresses of the hosts they serve through BGP update messages, using a dedicated address family. Other VTEPs receive these advertisements and populate their forwarding tables accordingly, without requiring BUM traffic for address learning.

Two BGP EVPN route types are of particular relevance to VXLAN deployments. Type 2 routes advertise MAC and IP address reachability for individual hosts. Type 3 routes, known as inclusive multicast routes, allow VTEPs to discover one another for the purpose of handling residual BUM traffic that still needs to be flooded, such as Address Resolution Protocol requests.

BGP EVPN also supports integrated routing and bridging, a capability that allows a single device to perform both Layer 2 bridging and Layer 3 routing within the same overlay. Two models exist for this function: in the asymmetric model, both the ingress and egress VTEP must be configured with all relevant subnets, while in the symmetric model, routing and bridging are separated into distinct stages, which reduces the configuration burden on VTEPs handling large numbers of subnets. Each model presents different trade-offs between the length of the forwarding path and the amount of state each VTEP must maintain.

Compared with flood-and-learn, BGP EVPN reduces the volume of BUM traffic in the network, provides faster convergence when hosts move or fail, and supports active-active multihoming, where a single host or server is connected to more than one VTEP simultaneously for redundancy. As a result, BGP EVPN is the control plane used in most modern data centre fabrics built on a spine-leaf architecture, where leaf switches act as VTEPs and the spine provides IP connectivity between them.

## 2 Network Typologies

![Geographic Scope](https://lattice-walker.github.io/CipherOps/courses/networks/1illustrations/1GeographicScope.svg)

Networks are commonly classified according to the geographic scope they cover and the entities that own or operate them.

A Personal Area Network covers the range of an individual person and typically relies on short-range technologies such as Bluetooth or USB. A common example is the connection between a computer and a wireless headset or peripheral device.

A Local Area Network covers a building or a campus. It is typically built using Ethernet or Wi-Fi and is owned and operated by a single organisation, such as a business or educational institution.

A Metropolitan Area Network covers a city or a metropolitan region. It is often deployed by municipalities, universities, or carriers to interconnect multiple sites across an urban area.

A Radio Access Network is the portion of a mobile network that connects end-user devices to the core network via radio. It comprises base stations and their associated infrastructure and is a component of both 4G and 5G mobile architectures.

A Wide Area Network covers large geographic distances, often spanning countries or continents. Wide Area Networks are typically built using capacity leased from carriers and may include MPLS-based services, dedicated leased lines, or connectivity delivered over the public internet.

These distinctions are not always sharp. A large campus Local Area Network may span distances comparable to a Metropolitan Area Network, and the classification applied to a given network depends as much on ownership and the technology used as on its physical size.

The security implications of each network type also differ. A Local Area Network under the direct administrative control of a single organisation presents a different risk profile from a Wide Area Network that traverses infrastructure operated by third parties, where traffic may pass through networks the organisation does not control or monitor.

## 3 Carrier Networks

### 3.1 Internet Service Providers

An Internet Service Provider is an organisation that provides customers with access to the internet and related services. Internet Service Providers are commonly grouped into three tiers based on how they obtain reachability to the rest of the internet.

![Tiers](https://lattice-walker.github.io/CipherOps/courses/networks/5illustrations/Tiers.svg)

- Tier 1 providers are networks that can reach the entire internet through settlement-free peering arrangements, without purchasing transit from any other network. Examples include Lumen, Telia, and NTT.
- Tier 2 providers peer with some other networks but also purchase transit from Tier 1 providers in order to reach the portions of the internet not covered by their peering relationships.
- Tier 3 providers purchase all of their transit from upstream providers. These are typically regional or local Internet Service Providers serving end customers directly.

The physical infrastructure supporting these networks includes backbone routers, long-haul fibre optic links, submarine cables connecting continents, and points of presence where a provider's network is physically accessible for interconnection.

Each Internet Service Provider operates one or more Autonomous Systems, identified by an Autonomous System Number, which is used to identify the network in Border Gateway Protocol routing exchanges with other networks.

Organisations seeking to avoid a single point of failure in their internet connectivity commonly adopt multi-homing, connecting to more than one Internet Service Provider so that a failure or outage at one provider does not result in a complete loss of connectivity.

### 3.2 Peering and Transit

Two networks connect to each other and exchange traffic under one of two general commercial arrangements: transit or peering.

Transit is an arrangement in which one network pays another for full reachability to the rest of the internet. The paying network gains access to all destinations reachable by its transit provider.

Peering is an arrangement in which two networks exchange traffic destined for each other's customers directly, typically without any payment between the parties. Settlement-free peering, the most common form, occurs between networks of broadly comparable size and traffic volume, where neither party derives a clear net benefit from paying the other. Paid peering occurs when traffic ratios or network sizes are asymmetric, and one party compensates the other for the interconnection.

Peering can be implemented in two physical forms. 
- Private peering consists of a direct physical connection between two networks, usually established within a colocation facility.
- Public peering takes place over a shared switching fabric at an internet exchange point, allowing a single physical connection to reach multiple peers.

When two networks exchange traffic, they must also decide at which point in the network the handoff to the peer occurs. In hot-potato routing, a network hands off traffic to its peer as close as possible to the traffic's point of origin, minimising the cost borne by the originating network but potentially increasing latency for the receiving network. In cold-potato routing, the originating network carries the traffic further across its own infrastructure before handing it off, generally at greater cost to itself but with a shorter path on the peer's network.

Commercial disagreements between two networks can lead to de-peering, in which one or both parties terminate the peering relationship. Because peering is not compulsory, such disputes can result in degraded connectivity or path inflation for the end users of both networks until an alternative route is established.

### 3.3 Internet Exchange Points

An internet exchange point is a physical infrastructure that allows multiple networks to exchange internet traffic through a common switching fabric. By enabling direct interconnection between participating networks, an internet exchange point reduces their reliance on upstream transit providers, which can lower both cost and latency.

Internet exchange points are typically operated as neutral, non-profit or member-owned entities, rather than by a single commercial network. Notable examples include DE-CIX in Frankfurt, AMS-IX in Amsterdam, LINX in London, and the Equinix Internet Exchange.

Many internet exchange points offer route servers, which are shared Border Gateway Protocol speakers that allow a participant to establish a single BGP session with the route server rather than negotiating individual sessions with every other participant, simplifying multilateral peering.

Traffic volumes at major internet exchange points range from hundreds of gigabits per second to several terabits per second. The presence or absence of a local exchange point in a given region affects the latency and cost of internet connectivity for networks operating there, since traffic that would otherwise be exchanged locally may need to be routed to a distant location.

Internet exchange points also present specific security considerations. Route leaks, in which a network inadvertently announces routes it should not, and BGP hijacking, in which a network falsely announces ownership of address space belonging to another network, are risks associated with the open nature of exchange point peering. Resource Public Key Infrastructure, a framework for cryptographically validating the origin of BGP route announcements, is increasingly deployed to mitigate these risks.

## 4 CDN and Infrastructure Concentration

A Content Delivery Network is a geographically distributed set of servers that cache and deliver content closer to end users, with the aim of reducing the distance, and therefore the latency, between a user and the content they are requesting.

Content Delivery Networks direct user requests to a nearby or well-performing server through DNS-based routing, where different DNS responses are returned depending on the requester's location, or through anycast routing, where the same IP address is announced from multiple locations and standard routing directs the request to the topologically nearest one.

Cached content has traditionally consisted of static assets such as images, scripts, and video files. Increasingly, Content Delivery Networks also cache or generate dynamic and personalised content at the edge, through edge computing capabilities integrated into their platforms.

Within this architecture, the origin server holds the authoritative version of the content, while edge nodes store and serve cached copies to reduce load on the origin. The management of cached content involves cache invalidation, the process by which stale content is identified and replaced. This is commonly governed either by a time-to-live value that expires content automatically after a set period, or by explicit purge requests issued by the content owner.

The primary performance benefits attributed to Content Delivery Networks are reduced latency for end users, reduced load on origin infrastructure, and the ability to absorb sudden increases in traffic without overwhelming the origin.

Security functions are increasingly bundled with commercial Content Delivery Network services. These include Distributed Denial of Service mitigation, Web Application Firewall filtering of malicious requests, and Transport Layer Security termination, where encrypted connections are handled at the edge rather than at the origin. Major providers in this market include Cloudflare, Akamai, Fastly, and Amazon CloudFront.

### 4.1 Centralisation and Digital Sovereignty

A relatively small number of providers, spanning Content Delivery Networks, cloud computing platforms, and DNS resolution services, now handle a large share of global internet traffic. This concentration means that an operational failure at one of these providers can have effects extending well beyond its direct customer base.

Past outages at providers including Cloudflare, Fastly, and Amazon Web Services have caused disruptions to services operated by organisations with no direct commercial relationship to the affected provider, illustrating how dependency on shared infrastructure can create correlated failure across otherwise unrelated systems.

Concentration of infrastructure also has jurisdictional consequences. Data routed through, processed by, or cached within a foreign country can become subject to that country's legal framework, including its rules on government access to data. This concern is central to the concept of digital sovereignty, generally understood as the capacity of a state or organisation to control its own data, infrastructure, and connectivity.

Regulatory responses to these concerns include the data localisation and data protection requirements introduced by the General Data Protection Regulation in the European Union, as well as national and regional cloud initiatives, such as the Gaia-X project developed jointly by France and Germany, intended to promote infrastructure subject to local legal and regulatory oversight.

Dependency on infrastructure controlled by foreign providers raises additional risks, including exposure to supply chain leverage, obligations to comply with lawful intercept requests under foreign legal systems, and the effects of export controls that may restrict access to certain services or technologies.

The concentration of internet infrastructure in a small number of large providers is generally described as creating a tension between operational efficiency and systemic resilience: centralised infrastructure benefits from economies of scale and specialised engineering, but a failure or disruption at a single provider can propagate across a large number of otherwise independent services. Approaches used to mitigate this risk include multi-CDN strategies, where an organisation distributes its traffic across more than one Content Delivery Network provider, on-premise caching to reduce reliance on external infrastructure, and preference for providers subject to the jurisdiction in which the organisation operates.
